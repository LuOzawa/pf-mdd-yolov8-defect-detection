## 五、训练

### 5.0 训练前先跑 CBAM 自检（30 秒）

若打算使用 CBAM 改进，建议先确认注入链路在当前环境正常，避免花几小时训练后
发现注意力模块没挂上：

```bash
python tools/verify_cbam.py --data pfmd_tiled_dataset_refined/pf_mdd.yaml
```

预期最后输出：

```
  CBAM 模块数量: 4   包装层索引: [2, 4, 6, 8]
  总参数 11,184,156   可训练 11,184,140
  [OK] 预训练权重已加载，CBAM 已注入且全部可训练
```

### 5.1 完整训练（推荐在 GPU 机器上）

```bash
python train_baseline.py
```

默认参数：`yolov8s` / `epochs=200` / `batch=8` / `imgsz=640` / `AdamW` / `patience=20`。

**设备选择**：`pick_device()` 会自动检测，顺序为

1. `overrides={'device': '0'}` 显式指定
2. 环境变量 `YOLO_DEVICE`
3. 有 CUDA 用 `"0"`，否则 `"cpu"`

指定设备示例：

```powershell
# Windows PowerShell
$env:YOLO_DEVICE = "0"
python train_baseline.py
```

```bash
# Linux / macOS
YOLO_DEVICE=0 python train_baseline.py
```

### 5.2 小配置验证链路（无 GPU 时唯一可行的做法）

```bash
python -c "from train_baseline import train_baseline_yolov8; \
           train_baseline_yolov8(overrides={'epochs':30,'workers':0,'imgsz':640,'batch':4})"
```

目的只是确认能产出 `weights/best.pt`，不要指望指标。

### 5.3 带 CBAM 训练（改进一）

```bash
python -c "from train_baseline import train_baseline_yolov8; \
    train_baseline_yolov8(overrides={'cbam':'backbone','epochs':200})"
```

`cbam` 可选值：

| 值 | 含义 | 参数量 |
| --- | --- | --- |
| `backbone` | 主干网络的 4 个 C2f 后（推荐） | +43,912 |
| `neck` | 颈部网络的 4 个 C2f 后 | +51,592 |
| `all` | 全部 8 个 C2f 后 | +95,504 |

可叠加 `cbam_reduction`（通道压缩比，默认 16）调整参数量。

> 原理：ultralytics 训练时会从 `model.yaml` **重建模型**，直接对 `YOLO(...).model`
> 注入会被丢弃。本项目改用 `CBAMDetectionTrainer` 子类，在 `get_model()` 里
> 「构建 → 加载预训练权重 → 注入 CBAM」，所以 CBAM 是随机初始化参与训练的。

├── weights/{best.pt, last.pt}
├── results.csv                # 每 epoch 的 loss 与 mAP

## 七、滑窗推理（改进四）

```bash
# 单图 + 对照实验
python sliding_window_inference.py \
    --weights training_results/<run>/weights/best.pt \
    --source data/Defect_images/Defect_images/0001_002_00.png \
    --out runs/sliding_predict \
    --compare-direct

# 整个目录批量
python sliding_window_inference.py \
    --weights training_results/<run>/weights/best.pt \
    --source data/Defect_images/Defect_images \
    --out runs/sliding_predict --compare-direct
```

参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--tile-size` | 640 | 切块边长，需与训练一致 |
| `--overlap` | 0.25 | 相邻块重叠比例 |
| `--conf` | 0.25 | 单块置信度阈值 |
| `--iou` | 0.5 | 跨块融合 NMS 的 IoU 阈值 |
| `--compare-direct` | 关 | 同时跑整图直推，可直接作为消融数据 |

输出：

```
runs/sliding_predict/
├── predictions.json      # 每张图的原图坐标系检测结果
└── vis/<图片名>           # 画框后的可视化
```

`predictions.json` 中每张图含 `tiles`（切块数）、`num_detections`、`detections`，
开启 `--compare-direct` 时还有 `direct_num_detections`，可直接计算
「滑窗融合相对整图直推的召回提升」。

## 九、常见问题

**Q：`torch.cuda.is_available()` 返回 False，但机器有显卡**
装的是 CPU-only 版 PyTorch。卸载后按 CUDA 版本重装：
`pip uninstall torch torchvision` → `pip install torch --index-url https://download.pytorch.org/whl/cu118`

**Q：训练报显存不足 OOM**
降低 `batch`（8 → 4 → 2）或 `imgsz`（640 → 512）。也可以换更小的模型
`yolov8n.pt`。

**Q：`verify_pipeline.py` 报 `ModuleNotFoundError: No module named 'yaml'`**
`pip install -r requirements.txt`（PyYAML 在清单里）。

**Q：数据集 YAML 里的 path 指向旧目录**
`project_config.ensure_dataset_yaml()` 会在运行时自动改写为当前工作区路径。
也可手动删除 `pf_mdd.yaml`，脚本会重新生成。

**Q：训练很慢**
先确认用的是 GPU（日志里会有 `[OK] 检测到 GPU: ...`）。CPU 上训练这个数据集不现实。

**Q：`evaluate_model.py` 报找不到 run**
需要先完成一次包含 `weights/best.pt` 的训练。
